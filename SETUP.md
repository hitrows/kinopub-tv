# Установка kinopub-tv с помощью Claude

> **Человеку:** дай этот файл Claude (Claude Code или приложение Claude с доступом к терминалу)
> и напиши «поставь мне это». Дальше он сам задаст вопросы и проведёт по шагам.

---

## Инструкция для Claude

Ты помогаешь человеку поставить **kinopub-tv** — клиент Кинопаба для старого Samsung Smart TV.
Репозиторий: https://github.com/hitrows/kinopub-tv (в README описано, как всё устроено).

Схема: на домашнем сервере работает `proxy/proxy.py`. Телевизор ходит к нему по HTTP:
забирает само приложение (`/widgetlist.xml`, `/Widget/KinoPub.zip`) и данные (`/kp/...`).
Прокси ходит в Кинопаб по HTTPS.

### Как вести разговор

- Говори по-русски, просто и дружелюбно. Человек может быть не программистом.
- **Задавай по одному-два вопроса за раз.** Не вываливай всю инструкцию сразу.
- Всё, что можно проверить самому (порты, ОС, Docker, модель телевизора), проверяй командами, а не спрашивай.
- Инструкции для телевизора давай **короткими шагами с названиями пунктов меню по-английски**,
  как они написаны на экране: на этих моделях меню обычно английское. Если человек пишет, что видит
  что-то другое, попроси фото экрана.
- **Перед изменением существующих сервисов** на сервере (nginx, docker-compose других проектов, systemd)
  спроси разрешения и сделай резервную копию файла.
- **Никогда не спрашивай логин и пароль от Кинопаба.** Вход только по коду устройства (шаг 4).
- **Прокси — только для домашней сети.** Не открывай порт в интернет и не настраивай проброс на роутере.

### Шаг 1. Убедиться, что всё подходит

Коротко расскажи, что получится в итоге (приложение Кинопаба на телевизоре), и спроси:

1. **Есть ли активная подписка Кинопаба?** Без неё дальше смысла нет.
2. **Какой телевизор?** Модель (наклейка сзади или Menu → Support → Contact Samsung / Product Information)
   и, если человек знает, IP телевизора.

**Определи год по модели.** Буква после диагонали у моделей вида `UE42F5300`:
`E` = 2012, `F` = 2013, `H` = 2014, `J`/`K`/`M`/`N`/`R`/`T`/`AU`… = 2015 и новее.

**Если известен IP, проверь телевизор сам:**

```bash
curl -s -m 5 http://<TV_IP>:7676/smp_2_ | grep -E 'modelName|ProductCap'   # Orsay: есть modelName, ProductCap ...Y2013
curl -s -m 5 http://<TV_IP>:8001/api/v2/                                     # ответ JSON = это Tizen
```

- **Серии E, F, H (Orsay)** — подходит.
- **Tizen (2015+)** — не подходит. Честно скажи об этом и остановись. Для Tizen есть официальное приложение Кинопаба или сторонние клиенты.
- **2011 и старше (серии D, C)** — скорее всего не заработает, предупреди.

### Шаг 2. Сервер

Спроси, **на чём будет работать прокси**. Это должно быть устройство в той же сети, что и телевизор,
и включённое, пока смотрят: домашний сервер, NAS, Raspberry Pi, старый ноутбук. В крайнем случае
подойдёт и этот компьютер, но тогда он должен быть включён.

**Если сервер удалённый,** узнай, как туда зайти (обычно `ssh user@IP`), и проверь, что SSH работает.
Дальше выполняй команды там.

**Разведка (выполни сам):**

```bash
uname -a; cat /etc/os-release 2>/dev/null | head -2
docker --version; docker compose version
python3 --version
git --version
sudo -n true 2>/dev/null && echo "sudo без пароля" || echo "sudo с паролем"
ss -ltnp 2>/dev/null | grep -E ':80\s' || sudo lsof -iTCP:80 -sTCP:LISTEN 2>/dev/null   # кто занимает порт 80
hostname -I 2>/dev/null || ipconfig getifaddr en0                                       # IP в локальной сети
```

> Важно: **телевизор забирает список приложений только с порта 80.** Отсюда три варианта.

#### Вариант A. Порт 80 свободен, есть Docker (самый простой)

```bash
sudo mkdir -p /opt/kinopub-tv && sudo chown "$USER" /opt/kinopub-tv
git clone https://github.com/hitrows/kinopub-tv.git /opt/kinopub-tv
cd /opt/kinopub-tv && docker compose up -d
docker logs kinopub     # строка "TV uses http://<IP>/kp" — проверь, что IP правильный
```

Если IP в логе не тот (у сервера несколько сетей, VPN, Docker-мосты), задай его явно в `.env` рядом
с `docker-compose.yml`, например `KP_PUBLIC=http://192.168.1.50/kp`, и сделай `docker compose up -d`.

На macOS и Windows Docker Desktop не поддерживает `network_mode: host`. Там используй вариант C.

#### Вариант B. Порт 80 уже занят веб-сервером (nginx, Caddy, Traefik…)

Запусти прокси на другом порту только на localhost: `.env` рядом с `docker-compose.yml`:

```
KP_PORT=8096
KP_BIND=127.0.0.1
KP_PUBLIC=http://<IP сервера>/kp
```

Потом `docker compose up -d`. **После разрешения человека и бэкапа конфига** добавь в server-блок,
который отвечает на порту 80 по IP (обычно `default_server`):

```nginx
location = /widgetlist.xml { proxy_pass http://127.0.0.1:8096; }
location /Widget/ { proxy_pass http://127.0.0.1:8096; }
location /kp/ {
    proxy_pass http://127.0.0.1:8096/;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_set_header Range $http_range;
    proxy_buffering off;
    proxy_read_timeout 3600s;
}
```

Затем `nginx -t` и reload. Если nginx в Docker с `network_mode: bridge`, `127.0.0.1` из контейнера
не попадёт на хост: используй IP хоста или `host.docker.internal`. Тогда прокси нужно слушать
не только localhost.

Для Caddy — аналогичные `reverse_proxy` на те же пути.

#### Вариант C. Без Docker

Нужен Python 3.8+. Зависимостей нет.

```bash
sudo git clone https://github.com/hitrows/kinopub-tv.git /opt/kinopub-tv
sudo python3 /opt/kinopub-tv/proxy/proxy.py      # проверка; Ctrl+C
```

Порт 80 требует root на Linux. Для автозапуска создай `/etc/systemd/system/kinopub.service`:

```ini
[Unit]
Description=kinopub-tv proxy
After=network-online.target

[Service]
ExecStart=/usr/bin/python3 /opt/kinopub-tv/proxy/proxy.py
Environment=KP_DATA=/var/lib/kinopub-tv
Restart=always

[Install]
WantedBy=multi-user.target
```

Затем `sudo systemctl daemon-reload && sudo systemctl enable --now kinopub`.

На macOS sudo для порта 80 не нужен. Для автозапуска можно сделать launchd-агент или просто
запускать вручную. Предупреди человека, что Mac не должен засыпать.

#### Проверка (для любого варианта)

```bash
curl -s http://<IP сервера>/widgetlist.xml        # XML с <download>http://<IP>/Widget/KinoPub.zip</download>
curl -s http://<IP сервера>/kp/auth/status        # {"authorized": false}
```

Если на сервере есть файрвол (ufw, firewalld), порт 80 должен быть открыт **для локальной сети**.
Это тоже спроси перед тем, как менять.

### Шаг 3. (Если нужно) настройка через `sudo`

Если для чего-то нужен пароль sudo, не проси прислать его в чат. Дай человеку команду
и попроси выполнить её самому в терминале.

### Шаг 4. Вход в Кинопаб

```bash
curl -s http://<IP сервера>/kp/auth/start
```

Покажи человеку **код** (`user_code`) крупно и попроси открыть **https://kino.watch/device**
на телефоне или компьютере и ввести его. Код живёт около 5 минут. Потом опрашивай каждые 5 секунд:

```bash
for i in $(seq 1 60); do r=$(curl -s http://<IP сервера>/kp/auth/poll); echo "$r" | grep -q '"authorized": true' && { echo OK; break; }; sleep 5; done
```

Если код истёк, просто запроси новый. Токен сохраняется в `data/token.json` и сам обновляется.
Повторный вход не нужен, пока не удалишь этот файл.

### Шаг 5. Телевизор

Нужен IP телевизора, если ещё не знаешь: **Menu → Network → Network Status** (или IP Settings).
Телевизор и сервер должны быть в одной сети.

Включи режим разработчика и синхронизацию. Пункты меню зависят от года:

**Серия F (2013).** Проверено на UE42F5300.
1. **Menu → Smart Features → Samsung Account → Log In.**
   - Email: `develop`
   - Password: `sso1029dev!`

   Если такого аккаунта нет: **Create Account** с теми же данными, потом **Log In**.
2. **Smart Hub → Apps → More Apps → Options** (вверху справа) **→ IP Setting** → IP сервера.
3. **Options → Start User App Sync.** Подождать, пока скачается.

**Серия H (2014).** Не проверено, по описаниям в интернете.
1. **Menu → Smart Hub → Samsung Account → Log In.** Логин `develop`, пароль пустой (если не пускает — `sso1029dev!`).
2. **Smart Hub → Apps.** Выдели любое приложение и **зажми OK** на пульте → **IP Setting** → IP сервера.
3. Там же: **Start User App Sync.**

**Серия E (2012).** Не проверено, меню сильно отличается.
- Обычно: войти в Smart Hub под пользователем `develop` (красная кнопка **A** → Login), затем
  **Tools → Settings → Development → Server IP Setting** → IP сервера, затем **User Application Synchronization**.
- Если так не находится, поищи инструкцию для конкретной модели и попроси фото экрана.

Предупреди: синхронизация может удалить другие пользовательские (неофициальные) приложения, если они стояли.

**После синхронизации** в **Smart Hub → Apps** появится **KinoPub** с логотипом Кинопаба.
Рядом с логотипом в меню приложения указана версия, например `v0.7`. Если вход в шаге 4 сделан,
сразу откроется главная. Если нет, приложение само покажет код для kino.watch/device.

**Проверь,** что телевизор действительно сходил к серверу:

```bash
docker logs --tail 30 kinopub    # (вариант C: journalctl -u kinopub -n 30)
```

Там должны быть запросы с IP телевизора к `/widgetlist.xml`, `/Widget/KinoPub.zip`, а после запуска
приложения — строка `/log?v=...&reported=...` с размером экрана.

### Шаг 6. Подсказать про пульт

Коротко:
- **Return** — назад.
- В меню **▲▼** листают разделы по кругу.
- **Жёлтая** кнопка — сортировка в списках, «смотреть с начала» в карточке фильма.
- **Синяя** уменьшает интерфейс, если края обрезаются.
- В плеере:
  - **OK** — пауза;
  - **◀▶** — перемотка на 10 с, **⏪⏩** — на 1 мин, **CH** — на 5 мин;
  - **▲** — озвучка, **▼** — субтитры.

### Если что-то не так

| Симптом | Что проверить |
|---|---|
| Синхронизация ничего не нашла | `curl http://<IP>/widgetlist.xml` с другого устройства в сети; правильный ли IP в IP Setting; файрвол; телевизор и сервер в одной сети |
| Приложение открывается, но «сервер недоступен» | В архиве зашит неправильный адрес: проверь `TV uses …` в логе, при необходимости задай `KP_PUBLIC` и заново сделай Start User App Sync |
| Интерфейс обрезан по краям | Синяя кнопка (90%, 85%…) |
| Обновил файлы, а на телевизоре старое | Подними `VERSION` (например, 0.7 → 0.8), перезапусти прокси, снова Start User App Sync |
| Видео не стартует или вылетает | Строки `player_*` в логе прокси; попробовать другое качество (зелёная кнопка) |
| Нужно войти заново | Удали `data/token.json` и перезапусти прокси |
